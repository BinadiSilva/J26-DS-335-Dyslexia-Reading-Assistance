# Component 4 session data contract

This is the standalone PP1 input contract. A teacher can enter these observations directly; receiving them from other components is not required. Use pseudonymous learner IDs. Synthetic and collected observations are never pooled in a training experiment.

| Field | Meaning and accepted values |
|---|---|
| `learner_id` | Nonempty identifier, consistent across sessions; generated by the app |
| `source` | `synthetic` or `collected`, explicit for every row |
| `assessed_on` | Observed date in `YYYY-MM-DD`; cannot be in the future |
| `words_total` | Passage word count, integer 1–5000 |
| `correct_words` | Correctly read passage words, integer 0–words_total |
| `insertions` | Added words not in the passage, integer 0–5000 |
| `duration_seconds` | Measured reading duration, 1–7200 seconds |
| `fluency_score` | Educator-assigned rubric score 0–100, using a consistent rubric |
| `difficulty_level` | Educator-assigned passage level, integer 1–5 |
| `practice_minutes` | Observed practice minutes during the preceding seven days, 0–1680 |
| `reference_stagnation` | Optional independent reviewer label: true/false, 1/0 or blank |
| `notes` | Optional educator-only observation, max 2000 characters; omitted from training exports |

Fluency is not a percentage of BAS or a universally standardized scale. Difficulty levels and the fluency rubric must have consistent meanings within a study. Equal difficulty levels alone cannot establish that two passages are equivalent; an educator must assess comparability. The app's bounds are input constraints, not developmental norms.

The application recomputes these derived measurements on both web entry and CSV import:

- Correct words per minute = `60 × correct_words / duration_seconds`.
- Reading accuracy (%) = `100 × correct_words / words_total`.
- WER (ratio) = `(words_total − correct_words + insertions) / words_total`.

Incorrect and omitted passage words are included in `words_total − correct_words`; insertions are counted separately. WER can exceed one. Neither missing observations nor missing labels are replaced with zero.

Example fictional input (this single row is insufficient for training):

```csv
learner_id,source,assessed_on,words_total,correct_words,insertions,duration_seconds,fluency_score,difficulty_level,practice_minutes,reference_stagnation
EXAMPLE01,synthetic,2026-09-01,100,80,3,120,60,2,30,
```

This gives 40 correct words/min, 80% accuracy and WER 0.23. Derived fields need not be supplied in a CSV. If present, they are recalculated. Duplicate learner/date pairs, invalid counts, missing provenance and mixed sources are rejected. IDs are trimmed before duplicate checks.

## Prediction and evaluation

Four consecutive weekly assessments form an input sequence. Each has speed, accuracy, fluency, WER, difficulty and prior-week practice minutes. The target contains speed, accuracy, fluency and WER seven days after the latest input. Difficulty must be unchanged across the full training sequence, including the target. Inference assumes the next assessment will use unchanged difficulty.

Learner IDs, reference labels, future measurements and future intervention outcomes are excluded from features. The split separates learners, not individual rows. A CSV needs at least 15 eligible learners; each must have at least five weekly observations to contribute a training example. All observations remain reportable even when they cannot contribute a forecast.

The current predictor does not encode activity type, infer an intervention's effect, or learn an optimal practice schedule. The planner separately considers stored intervention history and outcomes. `practice_minutes` describes past practice, not a promised intervention effect.

For collected-data stagnation evaluation, have an independent reviewer supply the reference judgment for the newest assessed date. Do not derive labels from the same monitoring rule being evaluated. The optional label is not shown as a diagnosis or used to determine the displayed risk category.

## Intervention records

An approved plan stores a target skill, educator-edited activity, minutes, sessions per week, review days, rationale, goal snapshot, start date and baseline assessment ID. Only one intervention is active per learner. Follow-up must belong to the same learner and occur after its start date. Completion also records adherence and outcome notes.

Changes compare the saved baseline with the selected follow-up. Different difficulty levels are flagged as noncomparable. A gain of more than 0.5 in the target metric is labelled observed improvement; below −0.5 is observed decline; otherwise it is little observed change. This is a provisional display rule, not an established meaningful-change threshold. Before/after association is not causal efficacy.

Changing learner goals refreshes future proposals while preserving approved plan snapshots. Saved assessments and completed outcomes are not overwritten. Correcting a mistaken historical assessment requires a deliberate maintenance procedure; there is no silent web edit/delete action.
